架构 · 事件主题与生产化路径

order.created订单创建 → 触发风控检测
risk.passed / rejected风控通过/拦截（黑名单、频次、异常）
order.matching进入派单 → 匹配Agent 多维打分
driver.matched司机确定 → 路径Agent 规划
route.planned里程/时长就绪 → 定价Agent 报价
price.quoted基础价+里程费+动态溢价−券
order.paid / cancelled支付成功 / 取消（空驶补偿）
应用端：本页走演示口 /api/*；JWT 三角色业务口（/api/passenger · /api/driver · /api/admin）+ JPA/H2 重启持久化已落地——E2E 覆盖 admin 登录/黑名单/乘客下单支付/地理自洽/401 防线。生产化路径（面试如实说明）：
EventBus → RocketMQ/Kafka 削峰 Store → MySQL + Redis（GEO 司机位置） 路径规划 → 高德/百度 API 通知 → 短信网关 + 个推 压测 → locust / JMeter 自证指标
⚠️ 诚实声明：本页为应用端实时调度控制台——事件流、打分公式（距离45%·服务分25%·接单率20%·均衡10%）、 动态溢价与风控规则均为真实代码实现；订单/司机/黑名单落库 H2，重启不丢（E2E 含重启续单验证）； 「支撑 XX 万单/日」等高并发指标未压测前不写入简历，压测方法见 README。
